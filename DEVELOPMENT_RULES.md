# Правила розробки сайту

Цей файл описує домовленості для всіх подальших змін сайту на основі шаблону Tunis Tailwind.

## Головний принцип

Спочатку використовувати або змінювати наявний механізм шаблону. Не додавати дублікати стилів, розмітки чи JavaScript, якщо просте рішення вже є в коді.

## Позиціонування сайту

- Сайт подається як сайт game-development studio / бренду, а не як персональне CV.
- Перший екран має показувати назву студії, напрям роботи та ігри, а не портрет або персональну біографію розробника.
- Особиста сторінка та професійний досвід залишаються в розділі `About` / `Studio`, де можна пояснити, хто стоїть за студією.
- Основні дії на головному екрані: перейти до ігор або зв’язатися щодо співпраці.

## Перед будь-якою зміною

1. Знайти поточне джерело значення: Tailwind-конфігурацію, CSS skin, компонент, JavaScript або дані картки.
2. Визначити одне місце, яке має бути джерелом істини.
3. Змінити саме його та перевірити всі сторінки й адаптивні режими.

## Кольори та стиль

- Акцентний колір змінювати через наявну систему `assets/css/skins/` або централізовані токени Tailwind.
- Не прописувати один і той самий колір вручну в багатьох HTML-файлах.
- Не створювати нові style-блоки в HTML, якщо стиль уже належить CSS/Tailwind-системі.

## Контент

- Перед заміною демо-контенту знайти всі його пов’язані частини: текст, зображення, посилання, модальне вікно, відео й навігацію.
- Дані про проєкт тримати разом і в передбачуваній структурі.
- Не залишати демо-тексти, тестові посилання чи зображення в опублікованій версії.

## Простота та підтримуваність

- Обирати найпростіше рішення, яке підтримує наявну структуру шаблону.
- Не додавати бібліотеки, фреймворки або власні обхідні рішення без реальної потреби.
- Не дублювати HTML для схожих карток чи сторінок, якщо це можна зробити через наявний шаблонний патерн.
- Після кожної суттєвої зміни перевіряти desktop, mobile, посилання та консоль браузера.

## GitHub Pages

- Не використовувати PHP: GitHub Pages його не виконує.
- Контактну форму підключати до сумісного зовнішнього сервісу або замінювати на прямий канал зв’язку.
- Не зберігати великі оригінальні відео в Git-репозиторії; для сайту використовувати оптимізовані трейлери або відеохостинг.

## Безпечна робота

- Не редагувати оригінальну папку шаблону; зміни вносити лише до робочої копії сайту.
- Перед великими змінами зберігати робочий стан у Git.
